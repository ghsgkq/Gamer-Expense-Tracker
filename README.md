# 🎮 게이머 가계부 (Gamer's Expense Tracker)

**게이머 가계부**는 Google과 Apple 양대 스토어의 결제 내역을 한곳에서 통합하여 분석하고 관리할 수 있도록 돕는 웹 애플리케이션입니다. 이제 흩어져 있던 지출 내역을 하나의 대시보드에서 시각적으로 확인하고 자신의 게임 소비 패턴을 손쉽게 파악할 수 있습니다.

## ✨ 주요 기능

### 📊 **통합 분석 대시보드 (핵심 기능)**

  - **하나의 페이지에서 모든 것을\!**: `Google Play(.json)`, `Apple Store(.html)`, 그리고 `아이시움 라운지(.html)` 결제 내역 파일을 한 페이지에 모두 업로드하여 모든 지출을 통합된 데이터로 분석할 수 있습니다.
  - **플랫폼별 독립 분석**: 상단 탭 전환을 통해 전체/구글/애플/아이시움의 결제 데이터를 탭 이동만으로 손쉽게 전환하며 분리 분석할 수 있습니다. 탭을 이동해도 업로드한 파일은 그대로 유지되며, '초기화' 버튼을 누를 때만 지워집니다.

### 🧾 **상세 분석 기능 (공통)**

  - **💱 다중 통화 지원**:

      - 결제 내역에 포함된 원화(₩), 달러($), 엔(¥) 등 다양한 통화를 자동으로 감지합니다.
      - 감지된 통화 목록이 드롭다운 메뉴로 제공되며, 원하는 통화를 선택하면 모든 요약, 차트, 내역이 해당 통화 기준으로 필터링되어 표시됩니다.

  - **📝 사용자 정의 키워드 관리**:

      - '기타'로 분류된 항목을 원하는 앱으로 재분류할 수 있도록 사용자가 직접 키워드를 추가하고 관리할 수 있습니다.
      - 앱 이름과 관련 키워드를 등록하고, 개별 키워드 또는 앱 전체를 삭제할 수 있습니다.
      - 키워드 목록이 길어질 경우를 대비해 실시간 검색 기능도 제공합니다.
      - 추가·삭제한 키워드는 브라우저에 자동 저장되어 새로고침 후에도 유지되며, '기본값 복원' 버튼으로 언제든 초기 사전으로 되돌릴 수 있습니다.

  - **💰 전체 결제 내역 요약**: 선택된 통화를 기준으로 모든 스토어의 총결제액과 가장 많은 금액을 지출한 '톱 스펜딩 게임'을 한눈에 보여줍니다.

  - **📈 전체 통계 시각화**: 
    - **소비 추이 (꺾은선/막대)**: 선택된 통화를 기준으로 상위 게임들의 결제액 누적 추이(6개 월 단위 꺾은선) 및 연도별 결제 합계(누적 막대)를 표시합니다.
    - **🍩 소비 분포 (도넛 차트)**: 지출액 상위 6개 게임의 소비 점유 비중(%)을 보여주며, 가독성을 위해 나머지 군소 게임은 '기타'로 통합 집계하여 시각화합니다.

  - **📥 결제 내역 엑셀 내보내기**:
    - **전체 내역 추출**: 업로드한 모든 플랫폼의 결제 내역을 모아 엑셀 파일(`.xlsx`)로 내보냅니다.
    - **개별 게임 내역 추출**: 특정 게임 상세 내역 화면에서 현재 보고 있는 게임의 거래 내역만 골라 엑셀 파일로 저장합니다.
    - **통화별 총액 자동 집계**: 화폐 단위(₩, $, ¥ 등)가 섞여 있어도 왜곡이 없도록 시트 맨 하단에 통화별 합계 요약 행을 자동 추가하며, 텍스트가 잘리지 않도록 열 너비가 자동 최적화됩니다.

  - **🔍 게임별 상세 분석**:

      - 월별 결제액 요약 및 상세 내역을 아코디언 UI로 제공합니다.
      - 월별 지출액 변동 추이를 막대그래프로 시각화합니다.
      - 상품명 검색 및 최신순 정렬을 지원하는 전체 결제 내역 테이블을 제공합니다.

  - **⭐ 특정 게임 맞춤 분석 (트릭컬 리바이브)**: '트릭컬 리바이브'를 선택하고 통화가 원화(KRW)일 경우, 주요 과금 상품에 대한 별도 요약 및 전용 필터링 기능을 제공합니다.

  - **📦 트릭컬 리바이브 패키지 구성품**: 월별 내역과 전체 결제 내역의 상품명 아래에서 '구성품 보기'를 펼치면 아이템 이름·수량·아이콘을 확인할 수 있습니다.
    - `product/trickcal-revive/products.json`의 상품명과 매칭하며, Google 결제 상품명의 게임 접미사와 띄어쓰기 차이를 정규화합니다.
    - 영수증의 `트릭컬 패스1`은 `트릭컬 패스`로, `리바이브 패스`는 `개쩜 패스`로, `리바이브 패스[할인]`은 `개쩜 패스[할인]`으로 연결합니다. 결제 내역의 원래 이름은 유지하며 판매기간 비교와 누적 합산에 동일하게 적용합니다.
    - 같은 이름의 상품이 여러 개면 결제일과 `판매 시작일`·`종료일`을 비교합니다. 시작일과 종료일을 모두 포함하며, 해당 기간의 항목을 날짜 미확인 항목보다 우선합니다. 띄어쓰기가 다른 이름도 함께 비교합니다.
    - 맞는 판매기간이 없으면 날짜 미확인 항목만 후보로 남깁니다. 모든 후보의 기간이 결제일과 맞지 않으면 별도로 안내하고 합산에서 제외합니다. 단일 상품은 이름으로 연결합니다.
    - 기간 비교 후에도 여러 구성이 있으면 현금 상품의 가격을 비교하고, 그래도 구분되지 않으면 구성품 후보와 각 판매기간을 표시합니다.
    - 선택적 `매핑정보.영수증상품명후보` 별칭을 지원하며 직접 일치하는 상품명을 우선합니다. 판매기간으로 연결할 수 없고 `추정시즌`이 있는 경우에만 결제월로 시즌을 추정하고 이를 표시합니다.
    - `패스보상` 정보가 있으면 구매 보상과 전체 단계 달성 기준의 유료 단계 보상을 나누어 보여줍니다. 무료·조건 미확인 보상은 제외하고 업그레이드의 기존 단계 보상은 중복 포함하지 않습니다. 해당 정보가 없으면 JSON의 구성품 목록을 그대로 사용합니다.
    - 반복된 구성품은 수량을 합산하며, 가격이 없고 구성품이 비어 있는 상품도 '상품명 확인 · 구성품 정보 미확보'로 구분합니다.
    - 등록되지 않은 상품은 안내 문구를 표시하며, 아이콘이 없는 구성품도 이름과 수량을 보여줍니다.
    - 국내 '트릭컬 리바이브' 상세 화면에서만 제공합니다.

  - **🎒 나의 누적 보물창고 (베타)**: 트릭컬 리바이브를 선택하면 대시보드 상단에서 아이템별 누적 구성품을 아이콘·수량과 함께 확인할 수 있습니다.
    - 베타 기능으로 상품 매핑이나 수량 합산이 실제 구매·수령 내역과 맞지 않는 부분이 있을 수 있습니다. 참고용으로 확인해주세요.
    - 선택한 플랫폼·연도·통화의 결제 내역을 기준으로 합산하며, 주요 재화 카드와 전체 아이템 검색·정렬을 제공합니다.
    - 단일 구성품 후보만 합산하고, 복수 후보·구성품 미확보·미등록 상품·판매기간 불일치는 제외 내역으로 보여줍니다. 상품 목록 기준의 추정치이며 패스 보상은 전체 단계 달성 기준입니다.
    - 공유 보상 정보가 제공되면 같은 시즌의 공유 패스 단계 보상은 한 번만 합산하고 구매 보상은 각 결제에 반영합니다. 공유 단계 구성에 충돌이 있으면 해당 단계 합산을 보류합니다.

### 📱 **모바일 환경 최적화**

  - **반응형 디자인**: 스마트폰과 같은 작은 화면에서도 모든 기능이 자연스럽게 보이고 사용하기 편하도록 디자인되었습니다.
  - **카드형 테이블**: 화면이 좁아지면 '월별 결제 내역'과 '전체 결제 내역'의 테이블이 가로 스크롤 없는 깔끔한 카드 형태로 자동 전환되어 가독성을 높였습니다.

## 📁 프로젝트 구조

유지보수와 확장성을 높이기 위해 파일을 기능별로 분리했습니다.

```
.
├── index.html              # 통합 분석 페이지 (메인 대시보드)
├── css/
│   └── style.css           # 모든 페이지에 적용되는 공용 스타일시트
├── js/
│   ├── appKeywords.js      # 게임 이름 분류를 위한 키워드 사전 데이터
│   ├── parsers.js          # Google/Apple/아이시움 데이터 파싱 및 병합 로직
│   ├── common.js           # 공용 로직: 파일 업로드·병합, 키워드 저장, 업데이트 모달, 이스케이프
│   ├── main.js             # 메인 대시보드 상태 관리, 필터링, 차트 렌더링
│   ├── trickcalProducts.js # 트릭컬 패키지 구성품 매칭 및 아이콘 표시
│   ├── trickcalInventory.js # 아이템별 누적 합산 및 보물창고 화면
│   └── updateHistoryData.js # 파일 직접 열기용 자동 생성 업데이트 데이터
├── product/trickcal-revive/
│   ├── products.json       # 공개 상품 카탈로그 (개인 결제 내역과 별개)
│   ├── catalog.js          # 파일 직접 열기를 지원하는 자동 생성 상품 데이터
│   └── component-icons/   # 구성품 아이콘 및 icon-mapping.json
└── guide/
    ├── apple_guide.html    # Apple Store 구매 내역 다운로드 가이드 페이지
    ├── guide.html          # Google Play 구매 내역 다운로드 가이드 페이지
    └── icium_guide.html    # 아이시움 라운지 결제 내역 저장 가이드 페이지
```

## 🚀 사용 방법

1.  `index.html`을 브라우저에서 직접 엽니다. 또는 프로젝트 폴더에서 `python3 -m http.server 8000`을 실행하고 `http://localhost:8000`을 엽니다. 업데이트 내역은 두 방식 모두 지원합니다.
2.  상단 탭에서 원하는 모드(통합 분석 / Google Play / Apple Store)를 선택합니다.
3.  `Order History.json` (Google), `문제 신고.html` (Apple) 또는 아이시움 라운지 `HTML` 파일을 업로드합니다. (하나만 올려도 분석 가능)
4.  데이터가 분석되면 하단에서 차트와 상세 내역을 확인합니다.

-----

  - **Google 데이터**: [Google Takeout](https://takeout.google.com/) → 'Google Play 스토어' → `Order History.json` 다운로드
  - **Apple 데이터**: [Apple 문제 신고](https://reportaproblem.apple.com/) → 전체 내역이 보일 때까지 스크롤 → 페이지 저장 (HTML)
  - **아이시움 데이터**: 아이시움 라운지 로그인 → 결제 내역 페이지 → 페이지 저장 (HTML)

## 🛠️ 사용 기술

  - **HTML5 / CSS3** (반응형 그리드 및 모바일 친화형 카드 레이아웃)
  - **JavaScript (Vanilla ES6)** (클라이언트 사이드 SPA 및 데이터 파싱)
  - **Chart.js** (누적 추이 라인 차트, 연간 합계 스택 바 차트, 지출 분포 도넛 차트 시각화)
  - **SheetJS (xlsx)** (결제 내역 엑셀 내보내기 및 자동 열 너비 보정 지원)

## 검증

`updates.json`을 수정하면 `node scripts/build-update-history.cjs`로 파일 직접 열기용 `js/updateHistoryData.js`도 갱신합니다. `node scripts/build-update-history.cjs --check`로 원본과의 일치를 확인합니다. HTTP에서는 최신 JSON을 우선하고, 파일 직접 열기나 JSON 요청 실패 시 생성된 데이터를 사용합니다. `node --test tests/updateHistory.test.cjs`로 검증할 수 있습니다.

상품 JSON이나 아이콘 매핑을 수정하면 `node scripts/build-trickcal-catalog.cjs`를 실행해 파일 직접 열기용 `catalog.js`도 갱신합니다. `node scripts/build-trickcal-catalog.cjs --check`로 원본과의 일치를 확인할 수 있습니다. HTTP 환경은 원본 JSON을 읽고, `index.html`을 직접 여는 환경은 자동 생성 데이터를 읽습니다. 생성기는 공개 상품 JSON만 읽으며 개인 결제 파일은 참조하지 않습니다.

`node --test tests/trickcalProducts.test.cjs`로 패키지 매칭과 구성품 표시를 검증할 수 있습니다. 실제 결제 파일로 추가 검증하려면 `GAMER_TEST_ORDER_HISTORY` 환경 변수에 저장소 밖 원본 파일의 경로를 지정합니다. 검증은 파일을 메모리에서만 읽고, 주문 정보나 상품별 구매 내역을 출력하지 않습니다. 개인 결제 파일을 테스트 fixture로 복사하거나 커밋하지 마세요.
